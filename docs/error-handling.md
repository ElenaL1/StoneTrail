# Ошибки и логи

API отдаёт плоский JSON. Поле `requestId` добавляется к уже существующим `message`, `code`, `fieldErrors` и `retryAfterSeconds`.

```json
{
  "message": "Не удалось выполнить запрос. Попробуйте ещё раз.",
  "code": "internal",
  "fieldErrors": null,
  "retryAfterSeconds": null,
  "requestId": "req_..."
}
```

Тот же идентификатор приходит в заголовке `X-Request-ID`. Если клиент прислал безопасный id (латиница, цифры, `.`, `_`, `-`, 8–64 символа), сервер его сохраняет. Иначе создаёт новый. Переводы строк в заголовке отбрасываются.

## Коды и статусы

| Ситуация | HTTP | code |
| --- | --- | --- |
| Ошибка разбора тела, query или path | 422 | `validation` |
| Нет сессии | 401 | `invalid_credentials` |
| Нет прав или email не подтверждён | 403 | `forbidden` или `unverified` |
| Ресурс не найден | 404 | `not_found` |
| Дубликат email или ника | 409 | `email_taken` или `nickname_taken` |
| Другое нарушение уникальности | 409 | `conflict` |
| Слишком много попыток входа или регистрации | 429 | `rate_limited` |
| Сбой базы, который нельзя показать | 500 | `database` |
| Непойманное исключение | 500 | `internal` |
| База недоступна или таймаут соединения | 503 | `unavailable` |

Пользователь видит русское сообщение из `backend/core/messages.py`. В ответе нет SQL, адресов, stack trace и текста исключения.

Проверка прав остаётся на сервере: чужой черновик статьи не читается и не редактируется, чужой пост и комментарий нельзя изменить. Повтор POST, PATCH и DELETE автоматически не выполняется.

## Логи

Self-hosted процесс пишет JSON в stdout. Docker собирает эти строки. Уровень задаётся `LOG_LEVEL`: `debug`, `info`, `warning`, `error`. По умолчанию `info`, поэтому `DEBUG` в production выключен, пока переменную не поменяют.

- `DEBUG` — диагностика разработки.
- `INFO` — завершённый запрос: метод, шаблон маршрута, статус, длительность, `requestId`, `userId` если сессия уже разобрана.
- `WARNING` — ответы 4xx, в том числе validation и rate limit. Для validation в лог попадают имена полей, не значения.
- `ERROR` — 5xx. В запись добавляется stack.

Не пишутся пароли, cookie, заголовок Authorization, ключи API, тело запроса и пароль SMTP. Полный email в логе почты заменён доменом. Ссылка с токеном подтверждения пишется только при `AUTH_DEBUG_LINKS=true`; в production флаг выключен.

Найти ошибку: взять `requestId` с экрана или из ответа и найти ту же строку в логах контейнера backend.

## Анализ логов

Сырые production-логи во внешний сервис сами не отправляются. Сводка без stack и без полей с паролями, токенами и cookie:

```bash
docker logs backend | python scripts/summarize_logs.py
```

Скрипт считает 5xx, сбои базы, отказы доступа и маршруты. Эту сводку можно разобрать вручную.

1. Локальная модель читает только сводку. Данные не уходят наружу, нужен свой runtime.
2. Внешний API — только по явному запуску и только со сводкой. Нужны договор и запрет сырых логов.
3. Гибрид: агрегация всегда локально, наружу позже можно отдать обезличенный всплеск, если появится политика.

## Наблюдение

Сейчас достаточно JSON-логов и `GET /health`. При росте можно снимать долю 5xx и latency из этих строк одним экспортёром. Отдельный Prometheus внутри приложения не ставится.
